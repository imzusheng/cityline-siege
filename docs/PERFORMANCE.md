# 性能

所有数字来自真实浏览器（Headless Chromium → Microsoft Edge 120+，ANGLE Metal，Apple M4），
1600×900，devicePixelRatio 1，通过 `node scripts/play.mjs perf` 采集，
每个采样点先跑 6 帧稳定，再用 5 秒 rAF 计数求平均。

## 预算是怎么花掉的

| Pass | draw call | 顶点/实例 | 说明 |
| --- | --- | --- | --- |
| 地面 | 1 | 6 顶点 | 3072×2304 烘焙贴图 |
| 建筑 | 1 | 182,208 顶点 | 798 栋，静态 VBO |
| 道具 + 尸体 | 1 | ~3,300 实例 | 树 / 路障 / 尸体 |
| 单位 | 1 | ~3,000 实例 | 士兵 + 感染体 |
| 特效 | 1 | < 6,000 顶点 | 枪口焰 / 曳光 / 血 / 尘 |
| **合计** | **5** | — | 与单位数量无关 |

## 已经做过的优化（按优先级）

1. **空间划分**：两个 48 单位均匀网格。最近敌人、分离力、士气波及、踩踏压力全部走网格；
   邻居采样有硬上限（分离 ≤ 9 个，最近敌人按 9 格窗口）。没有任何 O(n²)。
2. **AI 更新频率（LOD）**：按到镜头的距离把僵尸分为 3 档，思考间隔 1/2/4 帧；
   位移积分始终执行，所以动作不会顿。人类只有 128 个，恒定为每帧思考。
3. **批处理**：全部建筑一次绘制；单位一次实例化绘制；道具一次；特效一次。
4. **可见性剔除**：不可见单位的实例仍然写入缓冲（成本极低），但建筑与地面由 GPU 裁剪；
   HUD 的世界标记在 2D canvas 上先做屏幕包围盒判断。
5. **LOD**：图集本身用 mipmap，战略视角下自动降采样；建筑立面用 128px 可平铺贴图 + 各向异性过滤。
6. **不降人物细节**：即使 3615 个单位，每个人的图集精度与动画帧数完全不变。

## 内存

| 资源 | 大小 |
| --- | --- |
| 单位图集 3072² RGBA + mipmap | ≈ 50 MB |
| 道具图集 1920² RGBA + mipmap | ≈ 20 MB |
| 地面贴图 3072×2304 RGBA + mipmap | ≈ 38 MB |
| 立面 16 层 128² 数组贴图 + mipmap | ≈ 2 MB |
| 建筑网格 VBO | 182,208 × 36 B ≈ 6.6 MB |
| 单位状态（3,000 个 JS 对象） | ≈ 4 MB |

## 启动耗时（M4，首次加载）

| 阶段 | 时间 |

| 城市生成 | ~45 ms |
| 人物图集烘焙（840 格 × 24 帧绘制） | ~400 ms |
