# 开源素材资源调研

结论先说：**当前版本仍然全程序化生成，没有引入任何外部素材。** 下面是调研结果、可用性判断，以及如果要引入应该怎么接。

## 1. 可用的开源素材源（按适合程度排序）

| 来源 | 许可 | 适合什么 | 本机可达 | 备注 |
| --- | --- | --- | --- | --- |
| **Poly Haven** (polyhaven.com) | **CC0** | 无缝贴图（沥青 / 混凝土 / 砖 / 屋面）、HDRI、少量建筑模型 | ✅ `api.polyhaven.com` 200 | 有公开 JSON API，可按 slug 直接取 1K/2K 贴图；分辨率档位齐全，最适合替换 `textures.ts` 里的立面与地面 |
| **Kenney** (kenney.nl) | **CC0** | 等距城市套件、车辆、道具、UI | ✅ 200 | 风格是低多边形卡通风；`Isometric` 标签下有 city kit。和本项目的「桌面微缩模型」调性接近，但需要重做成图集 |
| **OpenGameArt** (opengameart.org) | **混合** CC0 / CC-BY 3.0 / CC-BY 4.0 / GPL | 2D 精灵、tileset、音效 | ✅ 200 | 许可逐条目不同，必须逐个核对；质量参差 |
| **ambientCG** (ambientcg.com) | **CC0** | PBR 建筑立面、沥青、混凝土、金属 | ❌ 本机 HTTP 000（连接被阻断） | 素材最对口（有整套 Facade 分类），但当前网络取不到；换到能访问的网络时这是第一选择 |
| **itch.io / CraftPix** 免费区 | 混合，多数要求署名或禁止商用 | 角色精灵、tileset | — | 许可最杂，最容易踩坑，不建议进商业版本 |
| **Quaternius / KayKit** | **CC0** | 低模 3D 角色与建筑 | — | 本项目是 2D/2.5D，除非改成 Three.js 路线，否则用不上 |

## 2. 为什么这一版没有直接集成

1. **单文件交付**：`standalone.html` 现在是 146 KB。塞进 8 张 1K 立面贴图会变成 8–40 MB，手机端打开会明显变慢，也违背「双击即玩」的定位。
2. **风格一致性**：人物是 3D 骨架投影烘焙的微缩模型风格，建筑是程序化可平铺立面。混入真实照片贴图会让「远看是城市、近看是微缩小人」的调性断裂。
3. **可平铺性**：本项目的每个立面层都是严格无缝且可按世界尺度平铺的（一个 tile = 一层楼 = 3.5 m）。多数照片贴图在「1 tile ≠ 1 层楼」的情况下会出现窗户比例错乱。
4. **许可合规**：全程序化生成 = 零许可风险，可以直接商用和二次分发。

## 3. 这一版实际做的「贴图精细度优化」

全部在 `src/renderer/textures.ts`，不引入外部依赖：

| 项目 | 之前 | 现在 |
| --- | --- | --- |
| 立面贴图尺寸 | 128×128 | **256×256** |
| 立面贴图层数 | 16 | **32**（8 种材质 × 3 种破损度 + 5 条底层 + 3 种屋顶） |
| 破损变体 | 无 | **完好 / 陈旧 / 战损** 三档，每个建筑按 `damage` 自动选择 |
| 破损细节 | 无 | 烟熏、裂缝、剥落、弹孔（聚簇而非满天星）、破碎玻璃与残片、露出的楼板 |
| 地面烘焙 | 3072×2304 | **4096×3072**（0.64 px/单位） |
| 近距离地面 | 直接放大糊掉 | 叠加 **256² 可平铺细节噪声**（每 8.9 单位一格），任何 zoom 都保持颗粒感 |
| 平铺尺度 | 立面 8 单位 / 屋顶 16 单位 | 立面 **14 单位**（一个开间 ≈3.5 m）/ 底层 **20 单位** / 屋顶 **46 单位**，大建筑不再出现明显的重复花纹 |
| 屋顶 | 有明显可复制的污渍斑块 | 纯细颗粒噪声（大屋面上任何显著 motif 都会暴露重复） |
| 建筑配色 | 单一灰度 | 每栋楼带 ±8% 的冷暖偏移（`tintR/tintB`），同一条街不再像同一张贴图盖出来 |

## 4. 如果要把外部素材接进来

代码已经为此留好了接口，不需要改渲染管线：

1. **替换立面**：把 `buildFacadeTexture()` 里的 `drawWall()` 换成 `await loadImage(url)` + `ctx.drawImage`，仍然是 32 层 `TEXTURE_2D_ARRAY`，只是在离线和在线模式下各走一条分支。注意保持「一层楼一个 tile」的比例。
2. **替换地面**：`bakeGround()` 返回的是一个 canvas，直接改成先绘制外部贴图的平铺版本即可；细节层 `buildDetailTexture()` 保持不变，它负责近距离清晰度。
3. **内联策略**：如果一定要保持单文件，建议把贴图降到 256²、转 JPEG q=78 后 base64 内联，8 张约 160 KB —— 这是唯一能在「单文件」和「真实贴图」之间取得平衡的做法。

**我的建议**：优先用 **Poly Haven（CC0，可访问）** 替换「屋面 + 沥青」两类，这两类不涉及窗格比例问题，收益最大、风险最小；立面继续程序化，因为「一层楼 = 一个 tile」的严格比例关系是照片素材给不了的。
