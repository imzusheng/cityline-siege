# QA — 实际试玩记录

所有测试都在真实浏览器里跑真实代码，通过 window.__CITYLINE__ 自动化接口操作，而不是用桩函数。
截图来自这些运行本身，并且是逐张人工看过的（不是只跑通就算）。

## 0. 三轮返工记录（用户反馈 → 定位 → 修复 → 复验）

### 返工 1：路网交错、没有逻辑

现象：地图上到处是随机角度的圆角路块，街道互不连通，主次不分。

根因（三个叠加）：
1. 九个街区各自生成街道网格，朝向和间距都不同，还把整张地图铺满 —— 道路占了 55% 的地面，footprintHitsRoad 把 537/560 个候选地块全部拒绝，全图只放下了 8 栋楼。
2. 每个街区额外生成 2 条「随机角度支路」，在 lineCap: round 下渲染成一个个孤立的胶囊形色块，就是图上那些「莫名其妙的圈圈」。
3. 占位检测用 16 单位栅格加 floor/ceil 取整，把一栋 54 单位的楼登记成 80 单位，制造 838 次假碰撞。

修复：换成单一全局格网 + 街区抑制格线（见 ARCHITECTURE.md），删除全部随机支路，占位检测换成精确 AABB 索引。

复验：建筑 8 → 1459；道路折线 399 → 111；碰撞拒绝 838 → 0；地图上不再出现任何孤立路块。

策略 A（平均分兵三处）：两个节点先后失守，t ≈ 605 s 全线崩溃。

## 4. 已知限制

- 没有音频。
- 建筑是实心的：僵尸沿街道绕行，不会真的进屋作战，守军也不能躲进楼里。
- 镜头最远时（0.105x）单位被钳制在 4.2 px，此时只能读成一个有朝向的小色块。
- 旋转是 2D 战场的旋转，不是 3D 相机；建筑背面永远不会面向镜头。

### 返工 5：穿模（用户第三轮反馈：上一轮「去掉门洞」之后依然存在）

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 单位依然走进/穿过建筑 | `bakeNavFromBuildings()` 用「**格子中心**是否落在建筑矩形内」判定实心。NAV = 24 时一栋典型 38x38 建筑只含一个格心，于是只封掉 576/1444 平方单位 —— 约 60% 的建筑面积仍是可行走格。全城 15.0% 的建筑面积可走（685255 个采样点里 103097 个），922 栋建筑里 670 栋（72.7%）内部可走。`steer()` 只用点测试查这张粗糙的格，所以单位径直走进去 | 烘焙改成**保守栅格化**：格子只要与建筑轮廓有任何重叠就封。判定方式是把格子四角投影到建筑坐标系取包围盒再和建筑矩形求交，因为只测建筑自身两条轴，所以只会多报重叠、不会漏报 —— 不变量变成「开放格整格没有建筑」，这正是 `steer()` 点测试成立的前提 |
| 肉搏推挤能把人推进墙里 | `combat.ts` 僵尸击退（2.2 单位/次）、`ai.ts` 肉搏后撤（最高 26 单位/秒）、卡住抖动（±6）都是直接改坐标，从不查地形 | 三处统一改走新增的 `nav.slideMove()`，与 `steer()` 同一套贴墙滑行规则 |
| 兜底函数形同虚设 | `nav.pushOutOfWalls()` 定义了但全项目从未调用 | 改成按 `step` 逐步挪出实心格（不再瞬移到格心），并在 `steer()` 里每步调用 |

复验（三个城市种子 × 240 秒无头跑真实仿真，外加浏览器实拍）：

- 建筑内可走面积 14.96% → **0.00%**（0/685255 采样点）；内部可走的建筑 670/922 → **0/922**。
- 单位进入建筑的事件：士兵 1465 次 / 僵尸 2481 次 → **0 / 0**；最深穿入 38.6 单位 → **0.00**。
- 浏览器同机位、同时间（t = 150 s，3.6x）截图对照：修复前士兵站在楼体上、楼里有士兵；修复后整条防线绕建筑东侧与南侧弯过去，没有任何单位压在建筑体积上。
- 没有引入卡死：贴墙不动的僵尸（3 秒内位移 < 3 单位）均值 14.0 → 4.0。
- 连通性未受影响：14 个出生点全部可达目标，开放格 100% 可达，平均流场路径 116 → 117。
- **代价（难度偏移，待配平）**：实心格 17.9% → 25.9%，僵尸不再能从建筑内部抄近路、守军也不能再靠建筑躲避，压力明显集中。同一套「收缩 + 增援」战术从撑满 780 秒（17 人存活、市政厅 72%）变成 691 秒崩盘。这属于修复的固有后果，不是新的 bug；数值怎么调是设计决定，未改动。


### 返工 6：人物抽搐与模型细节（用户第四轮反馈，含「允许马赛克化，但尽量避免穿模」）

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 人物一直抽搐 | 两层叠加。① `advanceState()` 直接把「本 tick 实际位移 / dt」当速度做阈值判断，而这个值在人群里被同伴挡住时会瞬间掉到 0、下一 tick 又回到满速，于是士兵每秒数次跨过 idle/walk/run 边界，每次切换都从第 0 帧重播。② 更主要的是索敌：跟踪的僵尸一死，`firing` 立刻变 false，士兵要等下一次索敌（最多 0.48 秒）才重新举枪 —— 实测 240 秒内 `idle ↔ aim` 互相跳了 7155 / 5147 次 | `anim.ts` 新增 `pickLocomotion()`：速度做指数平滑、每个阈值带上有回滞区间、切换最小停留 0.16 秒，且 locomotion 之间切换保留相位不回到第 0 帧。`ai.ts` 给士兵加 `aimHold`（最后一次开火后保持举枪 0.45 秒），跟踪目标死亡时立刻重新索敌（不再等计时器）；由速度推导朝向的转向速率 6 → 3.2（瞄准仍是满速） |
| 模型太过简陋 | 每个部件只有 4 个顶点、纯色填充、1.4px 描边、四肢仅 5px 宽：头盔是一条线、手是一个圆、步枪是三根矩形、躯干是一个梯形 | 躯干改成八点轮廓（肩宽—收腰—胯）+ 背心、弹匣袋、肩带、腰带、臂章、背包，装具按躯干局部坐标系摆放而不是逐朝向手调；四肢改成带圆柱渐变的锥形管 + 球面圆角关节 + 护膝护肘；头部有颅骨/下颚/耳朵、眉影、眼鼻，头盔分穹顶 + 帽檐 + 中线高光 + 下巴带（另有奔尼帽 / 医疗十字 / 贝雷帽）；步枪有枪托、机匣、护木、枪管、枪口装置、准星、瞄具（带镜片反光）、握把、弹匣、两脚架、背带；整体按朝向做受光/背光分级 |
| 僵尸像一堆散开的肢体 | 支撑手的位置由步枪方向推导（`handR + weaponDir * 0.255`），和持枪手共线，正面看两臂叠成一束 | 僵尸左右手改为各自独立摆动（`Pose.handL` 显式指定），形成蹒跚交替的轮廓 |
| 肢体被精灵边界切掉（穿模） | 精灵四边形与图集单元一一对应，任何画出格子的部分都会被直接切掉。实测 840 个单元里 333 个（40%）贴到边界；`death` 动画最严重（98 个）——而 `'death'` 从未被任何代码使用（尸体是独立道具贴图）。格子只给了锚点上方 78px，但前伸的步枪在轴测投影下最多到锚点上方 93px，枪口一直是被切掉的 | 删掉从未播放的 death 动画（每类 6 帧）。用一个临时超大格子（224px）量出全部姿势的真实边界（右 67 / 左 37 / 上 93 / 下 22 px），据此把单元定为 136px、脚底锚点放在 94px，图集列数 32 → 26 |

复验：

- 抬枪/收枪抖动 0.40 → **0.103 次/秒**（最差士兵 0.51，改动前最差约 7 次/秒）；步态切换 0.031 次/秒；朝向切换 0.83 → **0.21 次/秒**（最差 7.8 → 1.3）。剩下的 0.68 次/秒是开火循环，本来就该动。
- 附带收益：目标死亡立即重新索敌，射击不再中断，240 秒击杀 1273 → 1367（伤亡 6 → 2）。
- 贴到格子的单元 **333/840 → 0/630**：全部 630 个单元都有余量（右 5px、上 7px、下 21px、左 33px）。僵尸走楼穿模的复测仍为 0（见返工 5）。
- 图集 3536²，烘焙 < 5 秒，全程 60 FPS。格子变大带来更多透明留白，因此把远景最小像素钳制 6.0 → 8.5，让远景里的单位大小和改动前一致。

### 返工 7：命令下不下去、以及人群里的闪烁与挤压（用户第五轮反馈）

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 按 2/3/4/5 后点击地图，士兵不动 | `onUp()` 只在 `dragging`（位移 > 5px）时才下达命令，**单击时如果工具不是框选，什么都不会发生**。玩家按了命令键、点了地图，得到的反馈是零。另外命令下达后会立刻把工具切回框选，连发命令必须每次重按 | 单击也下令：以落点为中心、垂直于「部队质心 → 落点」方向生成一条短阵线，语义与拖拽一致；工具保持挂载（按 1/Esc 取消），HUD 底部提示当前命令；双击选组只在框选工具下生效 |
| 右键「简单移动」永远不生效 | `pointerdown` 时右键一律被登记为平移，`onUp()` 又要求 `wasPanning == false` 才发移动命令 —— 这个分支永远进不去 | 右键拖拽继续平移，右键**单击**下达移动命令 |
| 按 R 不能增援（按钮上写着 R） | 快捷键表里根本没有 `KeyR` | 接上 `onReinforce()` |
| Q/E 旋转快一倍；A 既全选又参与 WASD 平移 | Q/E 在 keydown 里转一次、`update()` 里每帧又转一次；`A` 同时是平移键和全选键 | Q/E 只保留每帧平滑旋转；全选改为 `Ctrl/⌘A`（并更新按钮与帮助文字），WASD 平移不再和全选抢键 |

### 返工 8：抖动的真正成因（用户第六轮反馈）

前几轮分别修掉了动画状态机跳变、人群幽灵重绘和挤压，但用户仍看到抖动。这次不再猜指标，而是先做两个排他性实验：

| 实验 | 做法 | 结果 |
| --- | --- | --- |
| 渲染稳定吗？ | **暂停**模拟（世界完全静止），隐藏 HUD 只留画布，连拍 6 帧逐像素比对 | **全部 0 像素差异**。渲染没有任何不稳定，抖动 100% 来自状态在变 |
| 站位在抖吗？ | 按 tick 采样每个已到位士兵的位置，统计速度反向次数 | 站立时反向 **0.00 次/秒**、平均速度 1.6 单位/秒。站位没有自激振荡 |

排除了这两条之后，剩下的只有「速率不匹配」这一层——而这正是肉眼看到的抖：

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 移动是一步一顿 | 模拟固定 **25 Hz**，位置每 40 ms 才更新一次；在 60 Hz 屏幕上精灵会**保持 2~3 帧不动、然后跳一下**（快速僵尸每 tick 移动约 8 屏幕像素）。抖动率（每帧位移的标准差/均值）实测 2.2 | 渲染插值：每个单位记录上一 tick 的位置，渲染时按「当前帧落在两个 tick 之间的比例」做线性插值（`world.prevX/prevY` + `renderer.render(world, alpha)`），兵与曳光弹用同一个插值位置，避免枪口和弹道错位 |
| 动画节奏不匀 | `ANIM_FPS` 是 15 / 8.5 / 3.4 等值，和 25 Hz 的 tick 不整除，于是每个动画帧停留 1 或 2 个 tick（40/80 ms 交替），整片尸潮一起「打嗝」——听起来像抖动，其实是节奏不齐 | 所有帧率改成 25/n：run 12.5、walk 8.33、idle 3.125、aim 1.92、melee/hit 6.25，每帧都停留整数个 tick |

受控验证（把模拟临时降到 10 Hz，让 25 Hz 环境下看不见的步进现象暴露出来，其余条件完全相同）：

| 条件 | 士兵每帧位移抖动率 | 僵尸每帧位移抖动率 |
| --- | --- | --- |
| 无插值 | **2.41** | **2.23** |
| 有插值 | **0.31** | **0.03** |

恢复 25 Hz 后复测：士兵 0.17、僵尸 0.04；精灵切换节奏的标准差僵尸 0.48 帧、士兵 1.56 帧（士兵的波动来自 idle/walk/aim 混用不同帧率，不是节奏不齐）。渲染稳定性复测仍为 0 像素差异；建筑穿模 0；贴墙不动 0；240 秒整局回归正常（击杀 1306、伤亡 9）；单击下令仍然有效（质心到落点 1454 → 346，改守后稳在 452）。
