## 模块职责

### `map/city.ts` — 城市生成

**一张全局街道路网，而不是九个各画各的网格。**

早期版本让每个街区生成自己的街道网格（各自朝向、各自间距），结果是九个网格互相重叠、把整张地图铺成 55% 的道路，最后只能放下 8 栋楼；而且街区之间街道互不连通，再加上每个街区的两条「随机角度支路」，地图上到处是孤立的圆角路块。现在改为：

1. **全局格网**：`PITCH = 176` 单位，所有街区共用同一套格线，因此街道天然贯通。
2. **等级**：每 5 条格线一条主干道（44/58 宽），每 2 条一条街道（32），其余支路（20）。宽度由格线序号决定，所以路网有可读的主次结构。
3. **街区通过「抑制格线」形成**：商业/工业/仓储/政务/医疗区跨 2 格（大块地），住宅/老城跨 1 格（小块地），公园完全抑制（整块绿地）。判定规则是 `i % scaleLeft === 0 or i % scaleRight === 0`，所以任何街区的边界街道一定存在 —— 路网永远连通，不会出现断裂。
4. **街区是格网的极大连通矩形**，逐个扫描得到，再按地块尺寸切成 1–5 × 1–4 个地块。
5. **建筑尺寸跟随地块，地块尺寸跟随街区，街区尺寸跟随格网** —— 三层派生，不会出现越界。
6. **占用检测用精确 AABB 索引**（`SolidIndex`），不是栅格打点。早期用 16 单位栅格 + `floor/ceil` 取整，会把一栋 54 单位的楼登记成 80 单位，导致 838 次自相残杀的碰撞拒绝；换成精确 AABB 后拒绝数为 0，建筑数从 658 涨到 1459。
7. **三条手写斜向大道**打断格网（老城、商业区、东站），产生三角地块与广场。
8. **破损**：52% 完好、28% 陈旧、20% 明显战损；战损建筑会削掉顶部 1–3 层、换成本身的残缺体块，并在周围撒落瓦砾 / 弹坑 / 残骸道具。

结果：**1459 栋建筑**、111 条道路折线（格网 + 斜向 + 环园路 + 高架）、1300+ 棵树、11 种建筑原型 + 3 种衍生、高度 18–332 单位（4.5–83 m）、634 个街区。

### `map/nav.ts` — 导航与流场
- 267×200 的 24 单位网格，标记建筑与路障为不可通行。
- 多源 BFS（Dial 桶排序）从所有未失守目标扩散，得到距离场；再用 8 邻域取梯度得到流场。
- 地形代价（道路快、公园慢）与 `heat`（交火热度）共同参与扩散：
  人类射击会在网格里留下热度，热度衰减很慢，于是流场会自己绕开被打成绞肉机的街道——这就是“尸潮从缺口灌进来”的机制来源之一。
- 每 3.4 秒重建一次，53,400 格，单次约 2–3 ms。

### `simulation/orders.ts` — 战线系统
- 玩家画出的线段生成 `LineOrder`，沿法向按 12.6 单位间距、13.5 单位纵深铺槽位。
- 槽位分配顺序：先按兵种角色（霰弹/步枪在前，机枪/医护在后），再按士兵在线上的投影排序，
  所以展开后的东西向顺序和玩家画线的顺序一致，不会交叉。
- `refitOrder()` 每 0.75 秒把死亡士兵的槽位释放，让最近的、未交战的同伴流进去——**前排阵亡后后排补位**就是这样实现的。
- 单位保持大致队形而不会被永久钉在槽位里：槽位只是引力中心，人群由分离力和碰撞塑形。
- `advance` 命令让整条线连同槽位一起沿法向前进；接触时自动减速。

### `simulation/ai.ts` — 行为
人类状态机：`MOVE / DEPLOY / HOLD / ENGAGE / RETREAT / ROUT / RECOVER`。
士气由局部感染者密度、友军密度、最近受击时间决定；低于 14 时溃退，回到 46 且周围无敌时重新集结。
玩家命令永远优先于自动交战：`HOLD` 不会为了追远处目标离开槽位，`FORCE` 除非被完全挡住否则不停下。

僵尸状态机：`FLOW / CHASE / ATTACK / BREACH`。
- 有视野内人类 → CHASE；进入触及范围 → ATTACK。
- 否则跟随流场。
- 被挡住且压力累积 → 尝试侧向挤过；旁边有路障 → BREACH，打穿后解除该格的不可通行标记（流场下一轮就会改道）。

### `simulation/combat.ts`
射击包含瞄准时间、距离衰减、士气系数、移动惩罚、近战惩罚；
命中生成曳光弹与枪口焰（由渲染器根据 `shotT` 与图集里的炮口偏移量精确绘制），
未命中生成尘土。近战会把人推开，重躯命中时触发镜头震动。

### `simulation/director.ts`
时间表 + 自适应渗流控制器 + 目标血量结算（守军数量会显著降低节点流失速度）。

## 渲染管线（`renderer/`）

| Pass | 内容 | Depth |
| --- | --- | --- |
| 1 | 地面：一张烘焙好的 4096×3072 城市贴图（含道路、人行道、广场、焦痕、**所有建筑阴影**）铺在一个大四边形上，再叠加一层 256² 可平铺细节噪声保证近距离清晰；世界之外用程序化郊野填充 | off |
| 2 | 建筑：一次 `drawArrays`，约 400k 顶点。立面/底层/屋顶用 **32 层** `TEXTURE_2D_ARRAY`（8 材质 × 3 破损度 + 5 底层 + 3 屋顶），UV 按世界尺度平铺：一个 tile 恰好一层楼（3.5 m） | on |
| — | `gl.clear(DEPTH_BUFFER_BIT)` | — |
| 3 | 道具与尸体：树、路障、血迹、尸体（实例化，1920² 图集） | on |
| 4 | 单位：士兵 + 僵尸，一次实例化绘制（3072² 图集） | on |
| 5 | 特效：枪口焰、曳光弹、血、尘（动态顶点缓冲） | off |

**为什么清一次深度**：这是 2.5D 战术可读性的关键取舍。塔楼永远不会吞掉正在楼后作战的士兵，
但建筑之间仍然正确互相遮挡。这是刻意的，写在 `renderer.ts` 的注释里。

轴测投影与高度：
```
rx = (wx - camX)·cos(-rot) − (wy − camY)·sin(-rot)
ry = (wx - camX)·sin(-rot) + (wy − camY)·cos(-rot)
sx = rx·zoom + W/2
sy = (ry·0.70 − z·0.72)·zoom + H/2
depth = ry·0.70 + z·0.72        // 越大越近
```

### 人物烘焙（`renderer/figures.ts` + `atlas.ts`）
人物不是画出来的，是**摆出来的**：
1. 一个 3D 骨架（骨盆/脊柱/头/双臂/双腿/武器），身体空间 x=前方、y=右方、z=上方。
2. 每个动画帧给出一组关节角与手部目标点，手臂用两骨 IK 求解肘部。
3. 投影用与游戏相机**完全相同**的轴测公式，于是 45° 俯视下的透视缩短是物理正确的。
4. 各个部件按相机空间深度排序后绘制，因此手臂会正确地挡在躯干前后。
5. 8 个朝向中只有 5 个是手绘的，另外 3 个由 GPU 镜像 UV 得到（`u0 = (col+1)·cellW, du = −cellW`）。

一帧图集：7 种单位 × 5 朝向 × 24 帧 = 840 个 96px 单元，启动时程序化生成约 0.4 秒。
每一帧还会记录**炮口在图集中的像素偏移**，运行时渲染器据此把枪口焰和曳光弹钉在正在播放的动画枪口上。

### 空间划分
两个 48 单位均匀网格（人类 / 感染体）。所有邻近查询（最近敌人、分离力、士气波及、踩踏压力）
都走网格，邻居采样有硬上限，复杂度 O(n·k)。
LOD 只降低**决策频率**：距镜头 1100 单位内每帧思考，2400 内每 2 帧，更远每 4 帧；位移积分始终每帧执行。
